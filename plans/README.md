## Dependency notes

- Plan 001 lands first because the repository currently has no test suite and
  no Python CI; the only workflow deploys the project page.
- Plan 002 precedes all resource consumers so no new code embeds temporary
  `__GET__`/`__MAKE__` paths.
- Plan 003 defines shared types, normalization, and resource resolution used by
  every language-specific tool.
- Plan 005 promotes the existing 250-item draft rather than recreating the
  older 130-item design from the source prompt.
- Plan 006 must not turn benchmark hypotheses into phonetic facts. It requires
  explicit evidence references for any resolved pronunciation.
- Plan 008 preserves the upstream `word`/`pitch`/`note`/`pitch2word`/`bpm`
  contract and therefore follows the frontend type work.
- Plan 009 is the integration gate. It records blocked GPU inference without
  letting CUDA debugging prevent completion of the data/frontend milestone.

## Repository facts all executors should know

- Python package layout: `src/`; upstream package: `src/vocalrender/`.
- Supported Python: `>=3.10`; `.python-version` currently pins `3.10`.
- Build backend: setuptools; dependencies and dev tools are in
  `pyproject.toml`.
- Canonical install command from upstream is `python -m pip install -e .`; for
  development use `python -m pip install -e ".[dev]"`.
- The planning shell had neither `python` nor `uv` on `PATH`; executors must
  provision/activate Python before running verification rather than claiming
  tests passed.
- Formatting: Black, line length 120, Python 3.10 target. Linting: flake8.
- Tests: pytest; Plan 001 creates the baseline suite and CI.
- Git history commonly uses conventional prefixes, for example
  `docs: clarify checkpoint training differences` and
  `fix: require prompt-conditioned inference`.
- Upstream functionality must remain intact. Do not rewrite or broadly
  restructure `src/vocalrender/`.
- The existing VocalRender-Pro checkpoint is present locally under
  `pretrained_models/VocalRender-Pro/`, including a 73,448-token tokenizer.
- The current working tree already contains untracked `resources/` and
  `benchmarks/`; preserve user data and never reset or clean the tree.

## Milestone-wide hard boundaries

- Do not train or fine-tune a model in Milestone 0.
- Do not modify AudioVAE, LocDiT, LocEnc, or the upstream model architecture.
- Do not download additional corpora or checkpoints unless the operator starts
  a separate, explicit acquisition task.
- Do not invent a full Mongolian G2P, fixed Cyrillic-to-IPA table, or automatic
  phonetic scoring.
- Do not assume a downloadable dataset is redistributable or training-eligible.
- Do not commit checkpoints, raw audio, AudioVAE latents, or generated Music3
  audio.
- Do not add a GUI in this milestone.

## Findings considered and deferred

- **Immediate LoRA adaptation:** deferred until the frontend contract,
  tokenizer audit, benchmark evidence, and a licensed native-singing dataset
  exist. Starting earlier would make model changes impossible to interpret.
- **Comprehensive abbreviation/number expansion:** deferred because the source
  prompt explicitly limits normalization to safe, obvious operations.
- **Automatic phonetic scoring:** deferred because no validated acoustic phone
  recognizer or native reference protocol is established.
- **Hard-code the raw-text or explicit-phone architecture:** rejected for this
  milestone. Plan 008 carries pronunciation overrides as neutral metadata so
  raw text, explicit phones, and hybrid input remain experimentable.
- **Restore omitted name/company/clan datasets:** rejected as unrelated to the
  pronunciation, morphology, syllabification, speech, and SVS goals.
- **Rename the 250-item draft back to MN-PHON-130:** rejected because it would
  discard newer user work. Plan 005 validates and preserves all 250 items.

## Audit scope note

This was a focused planning pass, not a general correctness/security audit of
all VocalRender model code. Recon covered repository structure, packaging,
CI, score preprocessing and prompt construction, tokenizer setup, local
Mongolian resources, raw-speech layout, and the benchmark draft. Neural model
internals, distributed training, inference backends, and dependency
vulnerabilities were not audited.
